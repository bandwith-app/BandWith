Technical appendix

An overview of the architecture: how the app is built and where the data lives.

One codebase for every device

BandWith is a single web application written in React 18 and TypeScript, built with Vite and styled with Tailwind CSS 4. The same application runs in the browser and, packaged with Capacitor 8, as a native app for iOS/iPadOS and Android. The layout adapts to the size of the window (the wide layout from 744 × 600 px) and, on iPhone Duo, to the posture the system reports (closed, Book, Laptop, landscape).

Native features come from Capacitor plugins: biometric authentication (Face ID, Touch ID, fingerprint) and secure storage for quick sign-in and app lock; Bluetooth Low Energy for Stage without internet; push and local notifications; the share sheet and file system for PDFs and charts; haptics, keyboard, status bar, splash screen and an in-app browser for Google/Apple sign-in and for iReal Pro.

Backend: Supabase

  • Database: PostgreSQL managed by Supabase. Bands, members, events, quotes, contracts, transactions, songs, setlists, chats, gear and notifications are database tables.
  • Authentication: email and password (with email confirmation), Google and Apple. On the phone, the credentials for quick sign-in stay in the device's secure storage.
  • Realtime: Supabase realtime channels update open gigs, lineups, setlists, tasks, chats, online presence and the shared Stage mode instantly.
  • File storage: band logos, PDFs, song recordings, personal files.
  • Edge Functions (server-side code): sending email, sending push, member invites, account deletion, the deputies' calendar feed.

Privacy enforced on the server

The “who sees what” rules aren't just hidden in the interface: the database enforces them.

  • Row Level Security on every table: each person reads only the rows of their own bands, and only admins write gigs, quotes, contracts, setlists and pricing sheets.
  • Column permissions: a member reads their own fee and the logistics, never other people's fees or totals; every new readable column needs an explicit grant.
  • No anonymous access: tables can't be read without an account. The public pages (quote, deputy reply, rider) use dedicated functions that, given a secret 64-character token in the link, return only the fields they are meant to; the rider, for example, never returns the client or any fee.
  • Stage over Bluetooth: each gig has a secret key given only to active members; only phones with the key find the leader and accept its messages.
  • Personal data: a full export from Export my data, and account deletion with server-side erasure.

Notifications

Important events (a gig invite, a poll, a proposal, a chat message, a payout, changes in the band, replies from clients and deputies) create a notification in the database, shown in the in-app inbox. A server function sends it as a push through Apple's (APNs) and Google's (Firebase Cloud Messaging, that is Google Play services on Android) services to the registered devices, with an unread-count badge; the text is translated on the server into the recipient's preferred language. The app refreshes the device token at every launch, says in Settings when the phone is blocking notifications and, when it comes back from the background, fetches chats, the bell and the badge straight away. Chat delivery ticks turn double when the push reaches the recipient's phone. Urgent items also show an in-app alert, even with push switched off. On the web there is no push: the bell does the job.

Offline

The device keeps a local copy of bands, gigs and setlists (with the lyrics and charts of gigs already opened). The copy is tied to the role: it holds only what that role can read (a member never has the client or prices in the cache), and it only fills the screen until the server answers, never overwriting fresher data. Each time the band list loads, the app records the role per band; if it changes, it throws away that account's cached data (keeping the profile, the open band and the queue of changes) and loads it again for the new role, in both directions. Creating, editing and deleting gigs and rehearsals offline goes into a sync queue that starts on its own when the network comes back; a strip under the status bar shows the state (You’re offline · showing cached info, pending changes, Sync now). These don't work offline: saving the quote itself, sending messages, answering invites and joining a band, the first sign-in on a device, deleting a gig.

Languages

A built-in translation module covers the whole interface in six languages (English, Italiano, Español, Français, Deutsch, Português), with localised dates, amounts and times. Client documents follow the client's language; server pushes and emails follow each recipient's preferred language, saved on their profile.

Usage statistics

The Android and iOS apps can send anonymous usage statistics to Google Analytics for Firebase (the same Google Analytics property as the bandwith.fun site), only after the user's yes on that device. Until then the native settings keep collection off and every consent type denied, so even the first launch sends nothing. Only screen names are logged (Home, Calendar, Chats, Gig, Stage, Settings…), never ids, names or content. Ad storage, ad user data and ad personalisation are always denied; the apps don't use the advertising ID (no IDFA on iOS; the Android app removes the advertising ID and ad attribution permissions). The web app sends no statistics.

Hosting and distribution

  • Web: the app, the Academy guide (/academy/) and the public pages (quote, deputy reply, rider, unsubscribe) are published on Vercel at app.bandwith.fun.
  • iOS/iPadOS: a native app distributed through Apple's channels, which also handle its updates.
  • Android: a signed native app, distributed as an APK file from a fixed link to the latest version. The app checks by itself whether there is a new version (at launch and when it comes back from the background, at most every few hours), downloads it and hands it to the Android installer, which asks for confirmation (Update › Install).
  • Academy guide: it is built with the app and included in the native apps, so it opens offline too; its screenshots are captured on every device.
